# System Architecture & Workflow Handover: Vision-Based CAD Modeling Step Reverse Generation System MVP (Minimum Viable Product)

## 1. Project Overview
We are building a "Vision-Based CAD Modeling Step Reverse Generation System". The core philosophy is **Semantic-Geometric Decoupling**:
- A Multi-Modal LLM (Qwen2.5-VL) acts as the **Planner**, deducing topological operations (text prompts).
- A Diffusion Model (SDXL) acts as the **Renderer**, generating pixel-perfect geometry (masks and wireframes).

---

## 2. Experimental Workflow (The 4 Phases)
### Phase 1: Data Auto-Labeling (Qwen2.5-VL Inference for Dataset Creation)
**Goal:** Generate ground-truth text prompts (`prompt.txt`) for SDXL training.
- **Inputs:**
    1. `final_snapshot.png` (Global Context)
    2. `prev_depth_map.png` (Clean generation base)
    3. `operation_param.json` (Factual Constraints)
    4. `overlayed_all.png` (Target of the Painter)
- **Prompting Rule:** You can provide QWen with a prompt similar to this: "A painter has been given two images — prev_depth_map.png, final_snapshot.png. You need to provide them with a description that enables them to paint overlayed_all.png. Your description MUST NOT include numerical dimensions or internal CAD element IDs".
- **Output:** `prompt.txt` saved in the step directory.

### Phase 2: Diffusion Model Fine-Tuning (SDXL + ControlNet + IP-Adapter)
**Goal:** Train SDXL to render the geometric action based on the semantic prompt.
- **Architecture:** Standard `StableDiffusionXLControlNetPipeline`.
- **Inputs (Conditioning):**
    1. **ControlNet:** `prev_depth_map.png` (Converted to 3-channel RGB. Provides the clean geometric base).
    2. **IP-Adapter:** `final_snapshot.png` (Provides global shape reference).
    3. **Text Encoder:** `prompt.txt` (Generated from Phase 1).
- **Target (Loss Calculation):** `overlayed_all.png` of the CURRENT step.
- **Task:** The model learns to draw the yellow/cyan masks and red/green/blue/magenta wireframes precisely onto the clean depth map.

### Phase 3: MLLM Fine-Tuning (Qwen2.5-VL LoRA/SFT)
**Goal:** Train Qwen to act as the autoregressive planner during actual inference, where `operation_param.json` is NO LONGER available.
- **Inputs:**
    1. `final_snapshot.png` (Target goal).
    2. `prev_depth_map.png` (representing the current status).
- **Target:** The `prompt.txt` for the NEXT immediate operation.
- **Task:** Qwen learns to compare the current state with the final state and deduce the next logical CAD operation without needing the ground-truth JSON.

### Phase 4: Autoregressive Inference Loop (The Final Pipeline)
**Goal:** End-to-End reverse engineering of a novel CAD part.
- **Initialization:** Given $I_{final}$ and an base $depth_0$ (main_ref_depth.png).
- **Step 1 (Plan):** Qwen (from Phase 3) takes $I_{final}$ and $depth_k$, predicting $Prompt_{k+1}$.
- **Step 2 (Render):** SDXL (from Phase 2) takes $I_{final}$, $depth_k$, and $Prompt_{k+1}$, generating $G_{k+1}$ (`overlayed_all.png`).
- **Step 3 (Execute):** A downstream CAD parser (outside the scope of these neural networks) reads $G_{k+1}$, performs the boolean operation, and renders a new clean $depth_{k+1}$.
- **Loop:** Repeat until Qwen outputs a `<STOP>` token or the depth matches the final snapshot.

1. Overview
This dataset is designed to train the "Vision-Based CAD Modeling Step Reverse Generation System". The dataset records every step of the CAD feature modeling process, from a blank slate to the final part. The current phase primarily validates single-view rendering and generation, but the file system retains an extensible structure for multi-view data.

3. File Definitions
- main_ref_depth.png: A depth map containing only the primary reference plane, representing the state prior to modeling.

3.1 Sequence-Level Files
Located in the root directory of the [CAD_PART_ID]_[VIEW_SUFFIX] folder, representing the final global state of the part.
- final_snapshot.png: The color rendered image of the final part from this specific view. Purpose: Serves as the Global Context, fed into the MLLM to help it understand the macroscopic location of local features; also used as the reference input for the Diffusion model's IP-Adapter.

3.2 Step-Level Files
Located within the roll_back_index_{i} folders, representing the state changes at the i-th operational step.
- prev_depth_map.png: The depth map (grayscale) of the existing model before the current modeling operation is executed. Purpose: Serves as the spatial condition input for the ControlNet in the Diffusion model, providing a "clean geometric base".
- current_depth_map.png: The depth map (grayscale) of the existing model after the current modeling operation is executed.
- operation_param.json: The ground-truth parameters of the current modeling step (including operation type modeling_type, depth, construct_type, etc.). Purpose: Provides absolutely accurate underlying logic for the MLLM to generate training prompts, eliminating visual ambiguity.
- overlayed_all.png: (**CORE FILE**) The 4-in-1 Alpha blended composite image, similar to the preview of modeling operation in CAD software. A human-vision-friendly image created by overlaying the prev_depth_map, sketch_plane_mask, reference_mask, and colored_incremental_wireframe. Purpose: It is a preview image of a modeling operation, similar to those in modeling software. Serves as the "local context" image for the MLLM to understand the current operational step, and also functions as the Target image for the Diffusion model's image generation.

4. Global Core Rules & Visual Anchors
Rule A: Color Mask Encoding
- In overlayed_all.png, colors represent unique topological, geometric, and physical meanings:
    Mask:
    - Semi-Transparent Yellow masked area: Sketch Plane.
    - Semi-Transparent Cyan masked area: Reference Geometry (e.g., Path / Axis of Revolution).

    colored_incremental_wireframe:
    - Red (Solid Line): Reference 2D Sketch used in the current operation.
    - Green (Solid Line): Edges of the newly added solid entity in this step (Added Solid Entity / construct_type: "NEW", "ADD", ...).
    - Magenta (Solid Line): Edges of the entity cut or removed in this step (Removed Entity / construct_type: "CUT", "REMOVE", ...).
    - Blue (Solid Line): The termination face contour of the extrusion/sweep in this step (Termination Face).

2. 单个建模操作的表达方式具体说明
单个建模操作 (拉伸、旋转、放样等) 使用一张图 (overlayed_all.png) 表示，该图由以下四个图层合并而来：
a) prev_depth_map.png：当前建模操作执行前，模型的深度图 (灰度图)
b) sketch_plane_mask.png：指示草图基准面在 prev_depth_map 中的位置 (草图基准面位置为半透明亮黄色 (255,255,0,128)，其他位置透明)
c) reference_mask.png：指示参考几何体（例如旋转操作的旋转轴，扫描操作的扫描路径等）在 prev_depth_map 中的位置 (参考几何体位置为半透明青色 (0,255,255,128)，其他位置透明)
d) colored_incremental_wireframe.png： represents ONLY the **local feature** or **delta geometry** created/modified in this *specific* modeling step. It does NOT show the rest of the existing part. 该线框图包含四种颜色，每种颜色代表的含义如下：
- Red (纯红色线) (255,0,0): 当前操作引用的二维草图 (Reference 2D Sketch)。
- Green (纯绿色线) (0,255,0): 本步骤新增的实体边缘 (Added Solid Entity / construct_type: "NEW", "ADD", ...).
- Magenta (纯品红色线) (255,0,255): 本步骤切除/移除的实体边缘 (Removed Entity / construct_type: "CUT", "REMOVE", ...).
- Blue (纯蓝色线) (0,0,255): 本步骤拉伸/扫描的终止面轮廓 (Termination Face)。
各图层叠加顺序 (从最底层到最上层): prev_depth_map -> reference_mask -> sketch_plane_mask -> colored_incremental_wireframe

3. 如何将 overlayed_all 翻译成建模系统所需的指令
3.1. 从 overlayed_all 中分离四个图层
3.1.1. 分离 colored_incremental_wireframe.png 时，因为它在合并时处于最上层，未被任何其他像素遮挡，仅需将(255,0,0)，(0,255,0)，(0,0,255)，(255,0,255)位置的像素分离开 (建议使用 HSV 空间提取线框：不要在 RGB 空间判断红绿蓝线，应转换到 HSV 色彩空间设置色相 (Hue) 和饱和度 (Saturation) 的阈值提取，这比 RGB 空间抗噪能力强十倍。)

3.1.2. 分离剩下三张图
prev_depth_map.png 是由灰度图转为的 RGB 图，overlay_color只可能出现 (0,255,255), (255,255,0) 两种颜色，透明度固定为128。因为属于 prev_depth_map 的各个像素必然有 R=G=B ，利用该条件可筛选出被mask位置的像素。(无需逆推深度：在 Phase 4 中，你的系统上下文里其实已经保存着上一步完美的 prev_depth_map 数组。提取出 Mask 的布尔区域后，底下的深度值直接调用真实数据即可，千万不要用 $X = 2 \times B_{out}$ 去逆推生成图的深度，因为这会将 SDXL 的生成噪点放大两倍，导致 OCCT 建出的模型表面全是“麻点”。)
由于overlay_color只能从 (0,255,255), (255,255,0) 两种颜色选，这两种颜色中，必然有某个通道数值为零，其它两个通道数值相等，叠加到的 prev_depth_map (R=G=B) 上后，必然有叠加后的像素值 (R,G,B) 中有两个是相等的，其它一个不等，而该像素在叠加前的 prev_depth_map 上对应的像素值，必然是那个不等的像素值的两倍，从而可以还原被 prev_depth_map 上被 mask 的部分。进一步可计算出 sketch_plane_mask 和 reference_mask.

3.2. 从四个图层提取参数
通过 sketch_plane_mask 获得草图基准面位置，然后将result_frame中的红色部分投影到 sketch_plane，然后做矫正，对齐，获得草图。
参考几何体（例如旋转操作的旋转轴等）利用 reference_mask 定位。
拉伸深度、旋转角度等通过尝试的办法获得成型实体终止面离纯蓝色线最近的参数。

4. 不连续的建模步骤
绘制草图这种建模步骤不创建实体，因此不显示，而且拉伸等操作引用的草图可由 colored_incremental_wireframe 的红色部分投影得到，因此未考虑。当然这可能导致一些特殊的建模操作不被支持，这些暂时不考虑，后续再优化。

# System Architecture & Workflow Handover: Vision-Based CAD Modeling Step Reverse Generation System MVP (Minimum Viable Product)

## 1. Project Overview
We are building a "Vision-Based CAD Modeling Step Reverse Generation System". The core philosophy is **Semantic-Geometric Decoupling**:
- A Multi-Modal LLM (e.g., Qwen2.5-VL) acts as the **Planner**, deducing topological operations (element counter and bbox).
- A Diffusion Model (e.g., SDXL) acts as the **Renderer**, generating pixel-perfect geometry (masks and wireframes).

---

## 2. Experimental Workflow (The 4 Phases)

### Phase 1: MLLM Fine-Tuning (Qwen2.5-VL LoRA/SFT)
**Goal:** Train Qwen to act as the autoregressive planner during actual inference.
- **Inputs:**
    1. `final_snapshot.png` (Target goal).
    2. `prev_depth_map.png` (representing the current status).
    3. fixed text prompt:
    "
    Based on the part final image and the current part depth map, plan the next operation and output the following JSON format:
    {
        "operation": "type" (e.g., extrude_add, symmetric_extrude_cut, ...),
        "approx_sketch_shape": [[x0,y0,is_smooth], ..., [x_9,y_9,is_smooth]] (Draw a rough sketch using ten points in prev_depth_map),
        "sketch_plane_bbox": [ymin, xmin, ymax, xmax] (Draw a rectangle on the prev_depth_map to indicate the location of the sketch plane.) ,
        "reference_geom_bbox": [[ymin, xmin, ymax, xmax], ...] (Draw a rectangle on the prev_depth_map to indicate the location of reference geometry (e.g., revolve axis, sweep path).),
        "target_region_bbox": [ymin, xmin, ymax, xmax] (Draw a rectangle on final_snapshot to indicate the position of the entity built in the current step on the final model.)
    }
    "
- **Target:** The `instruction.json` for the NEXT immediate operation.
- **Task:** Qwen learns to compare the current state with the final state and deduce the next logical CAD operation.

### Phase 2: Overlay the `instruction.json` on images
**Goal:** Overlay the bbox and approx_sketch_shape from instruction.json onto final_snapshot.png and prev_depth_map.png.
- **Inputs:**
    1. `final_snapshot.png`.
    2. `prev_depth_map.png`.
    3. `instruction.json`.
- **Target:**
    1. Draw the `target_region_bbox` as indicated in `instruction.json` in red on `final_snapshot.png`.
    2. Draw the `reference_geom_bbox` as indicated in `instruction.json` in cyan on `prev_depth_map.png`.
    3. Draw the `sketch_plane_bbox` as indicated in `instruction.json` in yellow on `prev_depth_map.png`.
    4. Draw the `approx_sketch_shape` as indicated in `instruction.json` in red on `prev_depth_map.png`.
    5. Output the processed `final_snapshot.png` and `prev_depth_map.png` as `final_snapshot_tag.png` and `prev_depth_map_tag.png`
- **Task:** Reflects the bbox and `approx_sketch_shape` values output by MLLM graphically onto `prev_depth_map.png` and `final_snapshot.png`.

### Phase 3: Diffusion Model Fine-Tuning (SDXL + ControlNet + IP-Adapter)
**Goal:** Train SDXL to render the geometric action based on the semantic prompt.
- **Architecture:** Standard `StableDiffusionXLControlNetPipeline`.
- **Inputs (Conditioning):**
    1. **ControlNet:** `prev_depth_map_tag.png`.
    2. **IP-Adapter:** `final_snapshot_tag.png`.
    3. **Text Encoder:** text prompt with fixed structure: [Operation_Type (available in instruction.json from Phase 1)]: The portion highlighted by the red box in final_snapshot represents the geometry that must be constructed in the current modeling operation. You should use this global context to guide the analysis of all subsequent tasks. First, locate the sketch reference plane indicated by the yellow rectangle in prev_depth_map, then precisely overlay the exact sketch reference plane in yellow. Next, analyze the approximate sketch shape indicated by the red wireframe in prev_depth_map and infer the precise sketch required for the current operation, drawing the precise sketch in red. Then, locate the reference geometry indicated by the cyan rectangle in prev_depth_map, and precisely overlay the exact reference geometry position in cyan. Finally, determine the solid feature generated by the current operation. Draw the terminating faces of the generated feature in blue. If the operation adds material, draw the remaining generated edges in green. If the operation removes material, draw the remaining generated edges in magenta.`
- **Target (Loss Calculation):** `overlayed_all.png` of the CURRENT step.
- **Task:** The model learns to draw the yellow/cyan masks and red/green/blue/magenta wireframes precisely onto the clean depth map.

### Phase 4: Autoregressive Inference Loop (The Final Pipeline)
**Goal:** End-to-End reverse engineering of a novel CAD part.
- **Initialization:** Given $I_final$ and an base $depth_0$ (main_ref_depth.png).
- **Step 1 (Plan):** Qwen (from Phase 1) takes $I_final$ and $depth_k$, predicting $Instruction_{k+1}$.
- **Step 2 (Overlay Instruction):** Based on $Instruction_{k+1}$, obtain the $I_final_tag_{k+1}$, $depth_tag_{k+1}$.
- **Step 3 (Render):** SDXL (from Phase 3) takes $I_final_tag_{k+1}$, $depth_tag_{k+1}$, and $Prompt_{k+1}$, generating $G_{k+1}$ (`overlayed_all.png`).
- **Step 4 (Execute):** A downstream CAD parser (outside the scope of these neural networks) reads $G_{k+1}$, performs the boolean operation, and renders a new clean $depth_{k+1}$.
- **Loop:** Repeat until Qwen outputs a `<STOP>` token or the depth matches the final snapshot.

    1. `final_snapshot.png` (Target goal).
    2. `prev_depth_map.png` (representing the current status).
    3. fixed text prompt:
    "
    Based on the part final image and the current part depth map, plan the next operation and output the following JSON format:
    {
        "operation": "type" (e.g., extrude_add, symmetric_extrude_cut, ...),
        "sketch_description": "sketch description" (describe the sketch counter by plain text),
        "sketch_bbox": [ymin, xmin, ymax, xmax] (Draw a rectangle on the prev_depth_map to indicate the location of the sketch.) ,
        "sketch_plane_bbox": [ymin, xmin, ymax, xmax] (Draw a rectangle on the prev_depth_map to indicate the location of the sketch plane.) ,
        "reference_geom_bbox": [ymin, xmin, ymax, xmax] (Draw a rectangle on the prev_depth_map to indicate the location of reference geometry (e.g., revolve axis, sweep path).),
        "target_region_bbox": [ymin, xmin, ymax, xmax] (Draw a rectangle on final_snapshot to indicate the position of the entity built in the current step on the final model.)
    }
    "
- **Target:** The `instruction.json` for the NEXT immediate operation.
- **Task:** Qwen learns to compare the current state with the final state and deduce the next logical CAD operation.

### Phase 2: Overlay the `instruction.json` on images
**Goal:** Overlay the bbox and approx_sketch_shape from instruction.json onto final_snapshot.png and prev_depth_map.png.
- **Inputs:**
    1. `final_snapshot.png`.
    2. `prev_depth_map.png`.
    3. `instruction.json`.
- **Target:**
    1. Draw the `target_region_bbox` as indicated in `instruction.json` in red on `final_snapshot.png`.
    2. Draw the `reference_geom_bbox` as indicated in `instruction.json` in cyan on `prev_depth_map.png`.
    3. Draw the `sketch_plane_bbox` as indicated in `instruction.json` in yellow on `prev_depth_map.png`.
    4. Draw the `sketch_bbox` as indicated in `instruction.json` in red on `prev_depth_map.png`.
    5. Output the processed `final_snapshot.png` and `prev_depth_map.png` as `final_snapshot_tag.png` and `prev_depth_map_tag.png`
- **Task:** Reflects the bbox and `approx_sketch_shape` values output by MLLM graphically onto `prev_depth_map.png` and `final_snapshot.png`.

### Phase 3: Diffusion Model Fine-Tuning (SDXL + ControlNet + IP-Adapter)
**Goal:** Train SDXL to render the geometric action based on the semantic prompt.
- **Architecture:** Standard `StableDiffusionXLControlNetPipeline`.
- **Inputs (Conditioning):**
    1. **ControlNet:** `prev_depth_map_tag.png`.
    2. **IP-Adapter:** `final_snapshot_tag.png`.
    3. **Text Encoder:** text prompt with fixed structure: [Operation_Type (available in instruction.json from Phase 1)]: The portion highlighted by the red box in final_snapshot represents the geometry that must be constructed in the current modeling operation. You should use this global context to guide the analysis of all subsequent tasks. First, locate the sketch reference plane indicated by the yellow rectangle in prev_depth_map, then precisely overlay the exact sketch reference plane in yellow. Next, analyze the approximate sketch shape by [sketch description (available in instruction.json from Phase 1)] located at the red wireframe in prev_depth_map and infer the precise sketch required for the current operation, drawing the precise sketch in red. Then, locate the reference geometry indicated by the cyan rectangle in prev_depth_map, and precisely overlay the exact reference geometry position in cyan. Finally, determine the solid feature generated by the current operation. Draw the terminating faces of the generated feature in blue. If the operation adds material, draw the remaining generated edges in green. If the operation removes material, draw the remaining generated edges in magenta.`
- **Target (Loss Calculation):** `overlayed_all.png` of the CURRENT step.
- **Task:** The model learns to draw the yellow/cyan masks and red/green/blue/magenta wireframes precisely onto the clean depth map.

### Phase 4: Autoregressive Inference Loop (The Final Pipeline)
**Goal:** End-to-End reverse engineering of a novel CAD part.
- **Initialization:** Given $I_final$ and an base $depth_0$ (main_ref_depth.png).
- **Step 1 (Plan):** Qwen (from Phase 1) takes $I_final$ and $depth_k$, predicting $Instruction_{k+1}$.
- **Step 2 (Overlay Instruction):** Based on $Instruction_{k+1}$, obtain the $I_final_tag_{k+1}$, $depth_tag_{k+1}$.
- **Step 3 (Render):** SDXL (from Phase 3) takes $I_final_tag_{k+1}$, $depth_tag_{k+1}$, and $Prompt_{k+1}$, generating $G_{k+1}$ (`overlayed_all.png`).
- **Step 4 (Execute):** A downstream CAD parser (outside the scope of these neural networks) reads $G_{k+1}$, performs the boolean operation, and renders a new clean $depth_{k+1}$.
- **Loop:** Repeat until Qwen outputs a `<STOP>` token or the depth matches the final snapshot.

3. File Definitions
- main_ref_depth.png: A depth map containing only the primary reference plane, representing the state prior to modeling.

3.1 Sequence-Level Files
Located in the root directory of the [CAD_PART_ID]_[VIEW_SUFFIX] folder, representing the final global state of the part.
- final_snapshot.png: The color rendered image of the final part from this specific view. Purpose: Serves as the Global Context, fed into the MLLM to help it understand the macroscopic location of local features; also used as the reference input for the Diffusion model's IP-Adapter.

3.2 Step-Level Files
Located within the roll_back_index_{i} folders, representing the state changes at the i-th operational step.
- prev_depth_map.png: The depth map (grayscale) of the existing model before the current modeling operation is executed. Purpose: Serves as the spatial condition input for the ControlNet in the Diffusion model, providing a "clean geometric base".
- prev_depth_map_tag.png: On prev_depth_map, mark the location of the sketch reference plane with a yellow rectangle, mark the location of the reference geometry with a cyan rectangle, and depict the approximate sketch shape using red lines.
- current_depth_map.png: The depth map (grayscale) of the existing model after the current modeling operation is executed.
- final_snapshot_tag.png: On final_snapshot, mark the location of the feature created by the current modeling operation within the final model using a red rectangle.
- operation_param.json: The ground-truth parameters of the current modeling step (including operation type modeling_type, depth, construct_type, etc.). Purpose: Provides absolutely accurate underlying logic for the MLLM to generate training prompts, eliminating visual ambiguity.
- overlayed_all.png: (**CORE FILE**) The 4-in-1 Alpha blended composite image, similar to the preview of modeling operation in CAD software. A human-vision-friendly image created by overlaying the prev_depth_map, sketch_plane_mask, reference_mask, and colored_incremental_wireframe. Purpose: It is a preview image of a modeling operation, similar to those in modeling software. Serves as the "local context" image for the MLLM to understand the current operational step, and also functions as the Target image for the Diffusion model's image generation.

4. Global Core Rules & Visual Anchors
Rule A: Color Mask Encoding
- In overlayed_all.png, colors represent unique topological, geometric, and physical meanings:
    Mask:
    - Yellow masked area: Sketch Plane.
    - Cyan masked area: Reference Geometry (e.g., Path / Axis of Revolution).

    colored_incremental_wireframe:
    - Red (Solid Line): Reference 2D Sketch used in the current operation.
    - Green (Solid Line): Edges of the newly added solid entity in this step (Added Solid Entity / construct_type: "NEW", "ADD", ...).
    - Magenta (Solid Line): Edges of the entity cut or removed in this step (Removed Entity / construct_type: "CUT", "REMOVE", ...).
    - Blue (Solid Line): The termination face contour of the extrusion/sweep in this step (Termination Face).

def get_exact_operation_type_from_param(param_json_path) -> str:
    with open(param_json_path, 'r') as f:
        param_dict = json.load(f)

    type_str = param_dict['modeling_type']
    if type_str == 'other':
        return param_dict['raw_type']

    if 'is_symmetric' in param_dict and param_dict['is_symmetric']:
        type_str = 'symmetric_' + type_str

    if 'construct_type' in param_dict:
        if param_dict['construct_type'] in ('NEW', 'ADD'):
            type_str = type_str + '_add'
        else:
            type_str = type_str + '_cut'

    if 'draft_angle' in param_dict and param_dict['draft_angle'] is not None:
        type_str = 'draft_' + type_str

    return type_str
